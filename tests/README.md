# Validation Scenarios

이 폴더에는 자동화 테스트 통과 결과가 아니라, 공개 사례의 중요한 계약을 검증하기 위한 최소 시나리오를 기록합니다. 이번 미리보기 작업에서는 실행하지 않았습니다.

## 1. TTL 만료와 자원 회수

| 항목 | 내용 |
|---|---|
| 실행 조건과 입력 | 패킷 3개 중 1개만 도착한 트래픽의 시뮬레이션 시간이 TTL을 초과 |
| 예상 상태와 결과 | 실패 결과는 1회 발행, 남은 패킷 2개는 활성, 트래픽은 활성 상태 유지 |
| 실제 확인 결과 | 미실행. `ExpireTraffic`과 `TryFinalizeTraffic`의 조건을 정적 확인 |
| 검사 코드 또는 로그 | 결과 이벤트 횟수, `ActivePacketCount`, `ActiveTrafficCount` 확인 필요 |
| 검증 범위와 대역 | Play Mode. 시뮬레이션 시간과 풀을 제어할 대역 필요 |
| 시나리오 / assertion | 1개 시나리오 / 최소 4개 assertion: 상태, 통지 횟수, 패킷 수, 트래픽 수 |

추가 실패 계약: 드롭 이벤트 구독자가 예외를 던져도 패킷이 반환되고, 마지막 패킷이면 트래픽도 반환되는지 확인해야 합니다.

## 2. 비동기 저장 응답 순서

| 항목 | 내용 |
|---|---|
| 실행 조건과 입력 | 저장 A(version 1), 저장 B(version 2)를 시작하고 A 성공 응답을 먼저 또는 나중에 완료 |
| 예상 상태와 결과 | A의 응답은 version 2의 pending 상태를 바꾸지 않고, B 성공 후에만 pending이 false가 됨 |
| 실제 확인 결과 | 미실행. `version == localSaveVersion` 조건을 정적 확인 |
| 검사 코드 또는 로그 | 지연을 제어하는 `IAsyncSaveStorage` 대역과 로컬 JSON의 pending 값 확인 필요 |
| 검증 범위와 대역 | Edit Mode. 인메모리 로컬 저장소와 완료 순서 제어형 비동기 저장소 필요 |
| 시나리오 / assertion | 1개 시나리오 / 최소 3개 assertion: A 후 pending 유지, B 후 해제, 최신 로컬 데이터 유지 |

추가 실패 계약: 최신 업로드가 실패하면 pending이 유지되고, 다음 초기화 재시도 성공 뒤 해제되는지 별도 시나리오로 확인해야 합니다.
